CHƯƠNG 1 — TỔNG QUAN HỆ THỐNG

1.1 Mục Tiêu
Hệ thống Quản lý Đặt Lớp Học (Class Booking Management System) là ứng dụng web REST API tích hợp PostgreSQL, quản lý toàn bộ vòng đời yêu cầu đặt phòng học theo quy trình phê duyệt nhiều cấp với phân quyền rõ ràng theo 4 vai trò.

3.4 Xử Lý Server
	•	POST /api/v1/auth/register — Validate lại toàn bộ phía server
	•	Kiểm tra email & username unique → ERR_EMAIL_EXISTS / ERR_USERNAME_EXISTS
	•	Hash password: bcrypt(password, 12)
	•	INSERT user (status=INACTIVE, role=CREATOR, email_verified=false)
	•	Tạo email_verification_token (UUID), TTL 24h → gửi email link /verify-email?token=
	•	Response 201 → redirect /register-success

3.5 Màn Hình Thành Công /register-success

	•	Link 'Về trang đăng nhập'

⚠  Mã lỗi API — Đăng ký
   • 201 | SUCCESS                  | Đăng ký thành công
   • 400 | ERR_VALIDATION           | Dữ liệu không hợp lệ
   • 409 | ERR_EMAIL_EXISTS         | Email đã tồn tại
   • 409 | ERR_USERNAME_EXISTS      | Username đã tồn tại
   • 422 | ERR_PASSWORD_WEAK        | Mật khẩu không đủ phức tạp
   • 429 | ERR_RATE_LIMIT           | Quá 5 request/phút từ IP
   • 503 | ERR_EMAIL_SERVICE_DOWN   | Không gửi được email xác nhận

4.4 Xử Lý Server
	•	POST /api/v1/auth/login { username_or_email, password, remember_me }
	•	Tìm user → không tồn tại: ERR_INVALID_CREDENTIALS
	•	Kiểm tra locked_until > NOW() → ERR_ACCOUNT_LOCKED { unlock_at }
	•	Kiểm tra status ACTIVE → nếu không: ERR_ACCOUNT_INACTIVE
	•	bcrypt.compare() — sai: tăng failed_login_count; đủ 5 → lock 15 phút
	•	Đúng: reset failed_login_count=0, tạo Access Token JWT (RS256, TTL 15 phút)
	•	Tạo Refresh Token (UUID hash SHA-256), lưu DB, TTL 7d hoặc 30d
	•	INSERT login_history (IP, user_agent, status=SUCCESS)
	•	Response 200: { access_token, refresh_token, user: {id, full_name, role} }

⚠  Mã lỗi API — Đăng nhập & Đăng xuất
   • 200 | SUCCESS                  | Đăng nhập / Đăng xuất thành công
   • 401 | ERR_INVALID_CREDENTIALS  | Sai username/password (không tiết lộ field nào sai)
   • 403 | ERR_ACCOUNT_INACTIVE     | Tài khoản chưa kích hoạt
   • 423 | ERR_ACCOUNT_LOCKED       | Tài khoản bị khóa tạm (kèm unlock_at)
   • 429 | ERR_RATE_LIMIT           | Quá 20 request/phút từ IP
   • LOGIC | LOGIC-AUTH-001         | Replay Refresh Token → Revoke toàn bộ session + alert Admin

5.5 Xử Lý Server Reset Password
	•	POST /api/v1/auth/reset-password { token, new_password, confirm_password }
	•	Hash token → tìm trong password_reset_tokens — kiểm tra TTL + used=false
	•	Validate: MK mới đủ mạnh, khớp confirm, không trùng MK cũ
	•	UPDATE users SET password_hash = bcrypt(new_password, 12)
	•	UPDATE password_reset_tokens SET used=true
	•	Revoke TẤT CẢ refresh_tokens của user → buộc đăng nhập lại
	•	Gửi email cảnh báo: 'Mật khẩu vừa được đặt lại. Nếu không phải bạn, liên hệ Admin ngay.'
	•	Response 200 → redirect /login?message=password_reset_success

⚠  Mã lỗi API — Quên Mật Khẩu
   • 200 | SUCCESS (always)         | Luôn trả 200 dù email tồn tại hay không (bảo mật)
   • 400 | ERR_TOKEN_INVALID        | Token sai, hết hạn, hoặc đã dùng
   • 422 | ERR_PASSWORD_WEAK        | MK mới không đủ phức tạp
   • 422 | ERR_PASSWORD_SAME_AS_OLD | MK mới trùng MK cũ
   • 429 | ERR_RATE_LIMIT           | Quá 3 request/giờ từ cùng email

	•	Client redirect bắt buộc về /profile/change-password — chặn mọi route khác
	•	Sau khi đổi xong → UPDATE must_change_password=false → vào hệ thống bình thường

6.4 Xử Lý Server
	•	PUT /api/v1/auth/change-password { current_password, new_password, confirm_password }
	•	bcrypt.compare(current_password, hash) — sai → ERR_WRONG_CURRENT_PASSWORD
	•	Validate MK mới: đủ mạnh + không trùng MK cũ
	•	UPDATE password_hash, Revoke TẤT CẢ refresh_tokens
	•	Gửi email cảnh báo thay đổi MK
	•	Response 200 → Client xóa tokens → redirect /login

⚠  Mã lỗi API — Đổi Mật Khẩu

E.2 Bảo Mật
	•	Mật khẩu: bcrypt salt=12. JWT: RS256, Access TTL=15min, Refresh TTL=7/30d
	•	HTTPS bắt buộc, CORS whitelist, Helmet.js security headers
	•	Rate limiting: 100 req/phút/IP public, 20 req/phút /auth/*
	•	Parameterized Queries (không raw SQL). Sanitize tất cả input. Content-Security-Policy
	•	File upload: kiểm tra MIME thực (magic bytes), không tin extension
	•	Audit log bất biến, mọi thao tác nhạy cảm đều ghi kèm IP + timestamp

E.3 Khả Dụng & Logging
	•	Uptime mục tiêu: 99.5% (không kể bảo trì)
	•	Health check: GET /api/v1/health → { status, db, uptime, timestamp }
	•	Structured JSON logging: timestamp | level | message | request_id | user_id
	•	Alert khi: error rate > 5%/phút | DB fail | disk > 85%
	•	DB backup hàng ngày, lưu 30 ngày
